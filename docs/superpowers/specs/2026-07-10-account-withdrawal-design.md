## A. 확정 — 회원탈퇴 정책

| # | 항목 | 결정 |
|---|------|------|
| 1 | 삭제 방식 | **즉시·최종 처리 · 유예·복구 없음** — 요청 시 곧바로 처리. 구현상 **인증 신원(`auth.users`)·개인정보(`public.users`)는 삭제**(→ 재로그인 불가·PII 파기)하고, 보존 대상(리뷰·쿨다운 해시)만 남김. ※ 순수 soft-delete(행 유지)는 Supabase에서 `auth.users`가 남아 **로그인이 계속돼** 부적합 |
| 2 | 재가입 | **쿨다운 30일** — 탈퇴 시 개인정보 즉시 파기, **이메일 단방향 해시만 30일 보관**(재가입 차단 판정 전용) → 30일 후 해시도 파기 |
| 3 | 포인트·열람권 | **전액 소멸** ("탈퇴 시 잔여 포인트·열람권은 소멸됩니다" 고지) |
| 4 | 리뷰 | **익명 보존** — 내용 유지, 작성자만 "탈퇴한 사용자"로(닉네임·프로필 끊음, `SET NULL`) |
| 5 | 탈퇴 확인 UX | **문구 타이핑** — "탈퇴합니다" 정확 입력해야 실행 + 사라지는 것 안내(리뷰 익명화·포인트/열람권 소멸·30일 재가입 제한) |

### 데이터 처리 요약 (탈퇴 시)
- **즉시 파기**: 이메일(평문)·이름·프로필(학과·학년·지역·입학연도·학적 등)·비밀번호 등 개인식별정보
- **익명화 후 보존**: 리뷰(작성자 `SET NULL`), 포인트·거래 기록(정산·어뷰징 방어용, 개인식별 제거)
- **해시만 30일 보관**: 이메일 단방향 해시 (재가입 쿨다운 전용) → 30일 후 파기

> ⚙️ 구현 주의: `auth.users` 삭제는 클라이언트가 직접 못 함 → **service_role / Edge Function**(현수). 순서: 삭제 **전에** 이메일 해시 계산·저장 → `auth.users` 삭제 → `public.users` cascade 삭제 → 리뷰 `SET NULL`. (컷오버로 예전 `deleted_at` 로그인 게이트는 사라져서, 행만 남기는 soft-delete로는 로그인 차단이 안 됨)

## B. 세션 보안 (관련 · 방향만 · 구현 후순위)

탈퇴와 별개지만 같은 논의에서 나온 계정보안. **아직 미확정, 방향만 기록.**

### B-1. 프로필 수정 탭 = 비밀번호 재인증
- **목적**: 공용 PC에서 **로그아웃 안 하고 자리 뜬 세션** 방어 — 프로필 탭(PII 집중부: 학과·학년·지역·이메일) 노출 차단. 그 안의 탈퇴 버튼도 함께 보호.
- **방법**: 로그인 상태에서 입력한 비번으로 `signInWithPassword(email, 입력비번)` 재호출 → 성공=맞음. (서버/RPC 불필요, 단 인증 영역)
- **부작용 주의**: 재호출=재로그인이라 `onAuthStateChange`→`fetchMe` 재실행(깜빡임·중복호출). AuthContext(현수)에서 처리 필요.
- **캐시**: **무캐시(매 진입 재입력)** 권장 — 방치 세션 보호가 목적이고, 프로필 탭은 드물게 들어가 마찰이 작음.
- ⚠️ 진짜 보안 경계는 **RLS**(본인만 자기 데이터 수정). 이 게이트는 UX·PII 노출 마찰일 뿐.

### B-2. 유휴 자동 로그아웃 (방치 세션의 근본 방어)
- **값**: 유휴 **30분**. (확정: 2026-07-14) 구현 설계는 `2026-07-14-idle-logout-design.md` 참조 — 벽시계 단일 진실원천 · 15초 폴링 · 의존성 0.
- **방식(중요)**: 타이머만 믿지 말고 **타임스탬프 기반**.
  - 활동 시 `lastActivity`(메모리 변수) 갱신
  - **복귀 시**(`visibilitychange`→visible · `focus` · 앱 로드) 경과시간 계산 → threshold 넘으면 로그아웃
  - → 백그라운드에서 JS 타이머가 멈추는 문제 회피(**모바일/탭전환 대응**)
- **"창 넘어가면 즉시 로그아웃 아님"** — 넘어간 것만으론 안 함. 돌아왔을 때 누적 idle이 30분 넘었을 때만.
- **성능**: 활동 이벤트는 **1초 쓰로틀**로 `localStorage`에 `lastActive` 기록(+`passive` 리스너). ~~백그라운드 전환 시에만 저장~~ 은 폐기 — `lastActive`가 탭 간 동기화의 유일한 근거라 메모리 변수로는 성립하지 않는다(방치된 탭이 활동 중인 탭을 죽인다). 초당 1회 localStorage 쓰기는 무시 가능한 비용.
- `AuthContext`의 기존 **`logout()` 재사용** → 새 인증코드 거의 없음, 저위험.
- **후순위**: 멀티탭 활동 동기화, 로그아웃 임박 경고 모달.

## C. 구현 분담
- **프론트(배경록)**: 탈퇴 모달(문구 타이핑·안내 문구), 프로필 탭 비번 게이트 UI, 유휴 로그아웃 훅(`logout()` 재사용)
- **백엔드/인증(현수)**: 탈퇴 처리(`auth.users`/`public.users` 삭제 — service_role/Edge Function)·이메일 해시·30일 쿨다운·리뷰 `SET NULL`·RLS/RPC, `signInWithPassword` 재검증 래핑·세션 부작용 처리
- ⚠️ 인증 흐름(로그인/세션) 건드리는 부분은 담당(현수)과 조율 후 진행.

## D. 약관·개인정보처리방침 반영 항목
- 탈퇴 절차 + 즉시 처리(유예 없음)
- 재가입 30일 제한 + 이메일 해시 30일 보관 **목적·기간·파기** 명시
- 포인트·열람권 소멸
- 리뷰 익명 보존 고지
- (구현 시) 유휴 자동 로그아웃 안내
